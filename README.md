# MACHI EVENT DROP（イベント情報掲載サイト・雛形）

**データベース不要・JSONだけで運用できる**ミニマム構成のイベント情報掲載サイトです。

- 構成の参考：「みんまちDROP for 中之島」（カード一覧・カテゴリ絞り込みなどのUI構成）
- トンマナ（配色・フォント・余白・カードデザイン等）の参照元：
  [とうじょうRMO](https://tojo-rmo.github.io/lp/)
  白ベース×深いグリーン（`#2f7a43`）×ゴールド（`#b3923f`）の、落ち着いた地域密着型デザインに統一しています。
  フォントは参照元と同じ **Noto Sans JP + Inter** を使用。
- イベントカードをクリックすると、**詳細情報をモーダル（ポップアップ）表示**します。

---

## 1. ファイル構成

```
event-site/
├── index.html            … ページ本体（基本的に編集不要）
├── css/
│   └── style.css         … デザイン（配色・余白などのトークンは冒頭 :root に集約）
├── js/
│   ├── config.js         … ★サイト共通設定（文言・挙動・配色ルールなど）
│   └── main.js           … 描画ロジック／詳細モーダルの制御（基本的に編集不要）
├── data/
│   └── events.json        … ★イベントデータ本体（CMS代わり。運用で更新するのはここがメイン）
└── images/
    └── thumbnails/        … イベントのサムネイル画像を置く場所
```

日常的な更新は **`data/events.json` を差し替えるだけ** で完結するように設計しています。

## 2. イベントデータの更新方法（`data/events.json`）

配列の中に、イベント1件＝オブジェクト1つとして追加・削除・編集するだけです。

```json
{
  "id": "evt-001",
  "title": "リバーサイド・アートフェスティバル 2026",
  "thumbnail": "sample-art.jpg",
  "category": "アート・デザイン",
  "address": "大阪府大阪市北区中之島公園周辺",
  "url": "https://example.com/events/art-festival",
  "detail": "<p>川沿いの遊歩道と公園一帯を舞台に…</p><h3>見どころ</h3><ul><li>夜間ライトアップ</li></ul>"
}
```

| 項目 | 必須 | 説明 |
|---|---|---|
| `id` | ○ | 一意のID。他のイベントと重複しない文字列（英数字推奨） |
| `title` | ○ | イベントタイトル。カード見出し・モーダル見出しに表示 |
| `thumbnail` | 任意 | `images/thumbnails/` 内の画像ファイル名（例: `sample-art.jpg`）。空欄や画像が存在しない場合は、カテゴリ名入りのプレースホルダーが自動表示されます |
| `category` | 任意 | カテゴリ名（自由入力）。新しいカテゴリ名を入れると、フィルターやカテゴリ色も自動で追加されます |
| `address` | 任意 | 開催場所・住所。ピンアイコン付きで表示 |
| `url` | 任意 | 公式サイトのURL。カード詳細モーダル内の「公式サイトを見る」ボタンのリンク先（新しいタブで開きます） |
| `detail` | 任意 | **カードをクリックした際に表示される詳細説明文。HTMLタグがそのまま有効になります**（下記参照） |

- **項目の追加・削除・並び替えは自由**ですが、`id` と `title` は表示上必須項目として想定しています。
- 配列の並び順 = サイト上の表示順（新しいものを先頭に追加するのがおすすめです）。

### `detail` にHTMLを書く場合の注意点

`detail` の中身はエスケープせず、そのままページに埋め込まれます（＝タグが有効になります）。
使用できるタグの例：

```html
"detail": "<p>本文の説明文です。</p><h3>見出し</h3><ul><li>箇条書き1</li><li>箇条書き2</li></ul><p><b>開催期間：</b>9/19〜9/27</p>"
```

- `<p>` `<h2>` `<h3>` `<ul><li>` `<ol><li>` `<b>` `<strong>` `<a>` `<img>` などが利用可能です。
- 見出し（`<h2>` `<h3>`）や箇条書き（`<li>`）は、サイト全体のトーンに合わせた装飾が自動で適用されます。
- **JSONの中で改行やダブルクォートを使う場合はエスケープが必要です**（改行は `\n`、`"` は `\"`）。
- `detail` を省略・空欄にした場合は、`config.js` の `detailFallbackText`（「詳細情報は準備中です。」）が表示されます。
- **`detail` は運用者が入力する信頼できるHTMLである前提です**（外部ユーザーからの入力をそのまま入れる用途には使用しないでください）。

## 3. イベント詳細のモーダル表示について

- イベントカード（サムネイル・タイトルを含むタイル全体）をクリック、またはキーボードで
  フォーカスして Enter / Space を押すと、画面中央にモーダルが表示されます。
- モーダル内には「サムネイル／カテゴリ／タイトル／住所／`detail`の内容／公式サイトボタン」が表示されます。
- 閉じるには、右上の ✕ ボタン、モーダル外側のクリック、または **Escキー** をご利用いただけます。
- スマホ表示ではモーダルが全画面表示になります。

## 4. サイト共通設定（`js/config.js`）

サイト名・キャッチコピー・ボタン文言・カテゴリごとの色などを一箇所にまとめています。

主な設定項目：

| 設定キー | 内容 |
|---|---|
| `siteName` / `siteNameSub` | ヘッダー・フッターに表示するサイト名 |
| `catchCopy` / `leadText` | ヒーローエリアの見出し・リード文 |
| `footerText` / `footerLead` | フッターの著作権表記・リード文 |
| `dataSource` | 読み込むJSONファイルのパス（差し替え可） |
| `thumbnailBasePath` | サムネイル画像フォルダのパス |
| `categoryColorMap` | カテゴリ名ごとに固定色を割り当てたい場合の対応表（省略可） |
| `categoryColorPalette` | `categoryColorMap` に無いカテゴリへ自動で色を割り当てるための色一覧 |
| `itemsPerLoad` | 初期表示件数・「もっと見る」1回あたりの追加件数（`0`以下で全件表示） |
| `officialSiteLabel` / `loadMoreLabel` | ボタン文言 |
| `detailHintLabel` | カード下部に表示する「くわしく見る」の案内テキスト |
| `detailFallbackText` | `detail`が未設定の場合に表示する文言 |
| `modalCloseLabel` | モーダル閉じるボタンのaria-label（読み上げ用） |

**新しいカテゴリを追加したい場合、`config.js` を編集しなくても `events.json` にそのカテゴリ名を書くだけで
フィルターに自動追加され、色も自動で割り当てられます。**（固定色にしたい場合のみ `categoryColorMap` に追記）

## 5. デザインの調整（`css/style.css`）

ファイル冒頭の `:root { ... }` にブランドカラーや角丸の大きさなどをまとめています。

```css
--green: #2f7a43;   /* ← メインカラーを変更する場合はここ */
--gold:  #b3923f;   /* ← アクセントカラー */
```

### PC表示について
コンテナ幅は参照元と同じ `max-width:1120px` に統一し、超ワイドモニターでもカード群が
間延びして見えないよう、カードグリッドは3カラム（960px以下で2カラム／640px以下で1カラム）に
固定しています。詳細モーダルも `max-width:660px` で頭打ちにし、PCで表示しても不自然に
横長にならないよう調整しています。

## 6. ローカルでの確認方法

`index.html` を直接ブラウザで開く（`file://`）と、ブラウザのセキュリティ制限により
`events.json` の読み込みが失敗する場合があります。必ず簡易HTTPサーバー経由で確認してください。

```bash
# event-site フォルダ内で実行
python3 -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```

## 7. 公開（デプロイ）方法

静的ファイルのみで完結するため、以下のような任意の静的ホスティングにそのままアップロードするだけで公開できます。

- GitHub Pages / Cloudflare Pages / Netlify / Vercel
- Azure Static Web Apps / AWS S3 + CloudFront
- 社内・レンタルサーバーのWebサーバー（Apache/Nginx等）にファイル一式を配置

**データベースやサーバーサイド処理は不要**です。イベント情報の更新は、公開後も
`data/events.json` をアップロードし直すだけで反映されます。
